# 05 · Workflows and rules

Behaviour source: `reference/logic/workspace-logic.js` and `admin-logic.js`. This doc summarises it; copy strings there are final.

## Case status machine
```
New ──Start verification──▶ Verifying
New/Verifying ──Approve identity──▶ In progress        (generates checklist of active data sources; System audit "Checklist generated (7 systems)")
Verifying ──Request more information──▶ Verifying       (infoRequested=true, portal message)
New/Verifying ──Reject──▶ Rejected                      (closed, email to requester)
any open status ──Extend deadline──▶ Extended          (max 2 months total; notice to requester; then continues like In progress)
In progress/Extended ──Send for approval──▶ Awaiting approval   (only when all pre-closure checks pass)
Awaiting approval ──Approve and close──▶ Completed      (Approver; final evidence pack generated by System)
Awaiting approval ──Request changes──▶ In progress      (Approver; notifies handler)
Awaiting approval ──Reject with documented reason──▶ Rejected  (Approver; template = Refusal)
Completed ──Send response / Copy for manual send──▶ (responseSent)
```

## Primary CTA by status (header)
| Status | Label | Icon | Disabled when | Note |
|---|---|---|---|---|
| New | Start verification | shield | – | – |
| Verifying | Approve identity | user-check | risk High and not Approver | "High-risk: approver role required" |
| In progress / Extended | Send for approval | send | any pre-closure check open | "N item(s) remain" |
| Awaiting approval | Approve and close | lock | not Approver, or checks open | "Approver role required" / "Resolve open items first" |
| Completed / Rejected | Download evidence pack | download | – | goes to Evidence tab |

## Pre-closure checks (`checks()` in seed — port exactly)
1. **Identity verified** — `idVerified`.
2. **All systems searched** — no system Not started / In progress (non-erasure: also not Action required).
3. **Evidence attached** — every Completed/Retained system has ≥1 evidence file.
4. Erasure: **Erasure outcomes resolved** — no Action required and none open. Others: **Redaction reviewed** — no tokens, or review done AND final export generated.
5. **Response template selected**.
6. **Exceptions documented** — every Retained system has reason AND exception category.

Each check has a `detail` string and target tab (see seed). Send for approval and Approve and close are blocked until all pass — enforce server-side.

## Data-source checklist rules
- Marking **Completed** requires ≥1 evidence file → inline error "Attach evidence before marking this system Completed."
- In progress / Completed: no reason. Not found / Action required / Retained under exception: reason dialog. Retained also requires exception category. Dialog copy: "Retention requires a documented exception. It appears in the evidence pack and must be reviewed by the approver."
- Bulk: Assign tasks (owner, optional note), Send reminders (to owners of selected or all open), Change due dates (must stay before statutory deadline), Mark as not found (reason).
- Owner change writes "{System} task reassigned to {name}".
- Default due = received + source default SLA days.

## Erasure outcome rules
- Outcome dialog: options = 5 outcomes, category required when Retained, reason required.
- Outcome maps to system status (docs/02). If outcome ≠ Action required and no evidence, the system auto-attaches an outcome record PDF (`{key}_outcome_{id5}.pdf`) — in production generate a real outcome record.
- "A case cannot enter approval if any system remains in Action required."

## Redaction rules
- Original file preview is hidden until "Open original · logged" (reason). Logged per viewer.
- Apply redaction requires category + reason (≥3 chars) → "A redaction reason is required."
- Any new redaction after review resets review to `none`.
- Handler: Request review → Approver: Complete review (reason) → Generate final redacted export (new file `_redacted_v2`, original kept as v1).

## Identity
- High-risk → only Approver can approve/reject. Handler may request more info.
- Approve: reason. Request more info: option (Additional account identifier / Proof of address / Government ID (masked)) + internal reason; SLA keeps running. Reject: documented reason; closes case.
- Opening an ID document: reason; logged with file ref.
- Production: email confirmation is a real signed link; identifier match is computed against a customer-provided lookup (manual by default per policy Tier 1 — handler marks match result).

## Extension
Options +1 month / +2 months; reason required; System logs "Extension notice sent to requester"; outbound email "We need more time to complete your request". If `approverReviewsExtensions`, route to Approver before notice (prototype applies immediately — production should add a pending state; see docs/08).

## Evidence pack
- Generate/Regenerate any time → new version (draft while open). Approval auto-creates a final version.
- Download PDF/ZIP → logged, signed link expires 24 h.
- Share signed link: expiry 24 hours / 7 days / 30 days (default 7) + "Recipient and purpose" reason. Link format `https://{portalHost}/e/{id5}-{token}`; access logged.
- Never gated by plan.

## Response
- Template drives `respText()` (port exactly). From address = workspace privacy email (or fallback sender).
- Send response only after Completed; optional note; logs Communications. "Copy response for manual send" copies text and logs "Response copied for manual send".
- `autoSendFinalResponse` default false.

## Reason-required actions (ReasonDialog)
Workspace (min 3 chars unless optional): Approve identity · Request more information · Reject request · Open ID document · Status Not found/Action required/Retained · Record outcome · Extend deadline · Send for approval (optional) · Approve and close · Request changes · Reject with documented reason · Send response (optional) · Share signed link · Open original file · Complete redaction review · Bulk assign owner · Bulk mark not found · Bulk assign tasks (optional) · Change due dates · Deactivate user · Go live (optional) · Take portal offline · Remove custom domain.

Admin (min 5 chars, always required): Change plan · Request support access ("Reason shown to the customer") · Require MFA · Suspend · Reactivate · Approve/Reject/Reject-and-reserve subdomain · Reserve/unreserve name · End support access · Change staff role · Remove staff · Change policy · Retry payment · Extend trial · Apply credit · Cancel at period end · Resume subscription · Refund payment · Void invoice.

Workspace billing (Settings › Billing & usage): Change plan (optional note) · Cancel subscription (required).

Each dialog shows an **audit preview**: "{actor} · {timestamp} · {action}". The exact `title`, `desc`, `confirmLabel`, `reasonLabel`, `placeholder`, `options` for each are in the logic files — copy them.

## Audit events
Write one event per mutation, same transaction. Fields: at, actor label (name, "System", "{Name} (requester)", "{Name} (customer)"), action (past-tense sentence, e.g. "Identity approved", "Stripe marked Completed", "Evidence pack v2 generated"), category, reason, object (file name / link), meta ("IP 81.2.69.142 · session 7f3a", "Automated", "IP … · portal"). Case audit categories and admin categories in docs/04. Exports (CSV) are themselves logged.

## Notifications (derived, per user)
Workspace — computed from open cases in the current workspace:
- **Approver**: "Approval needed" (Awaiting approval → overview) · "High-risk identity check" (risk High and New/Verifying → identity).
- **Handler**: "New request" (New) · "Changes requested" (last audit action starts with "Changes requested"; sub = reason) · "System needs action" (any Action required, not awaiting) · deadline: "Overdue by N day(s)" / "Due today" / "Deadline in N day(s)" when ≤5 days left and not awaiting.
- Meta "{caseId} · {sla label}". Unread tracked per user+key; "Mark all as read". Badge caps at "9+".
- Production: also email/Slack digests per SLA reminder days; escalation to escalation recipients at day 28/30.

## SLA reminders (job)
Daily job per open case: on reminder days (1, 7, 14, 21, 28, 30 from receipt, configurable) send owner reminders for open tasks; day 28+ escalate to escalation recipients; log "Day N reminder sent to …" as System. Cockpit "Next reminder" line mirrors this.

## Portal setup rules
- Subdomain: regex `^[a-z0-9][a-z0-9-]{1,28}[a-z0-9]$` → "Use 3–30 lowercase letters, numbers or hyphens. It can’t start or end with a hyphen." Reserved → "“{v}” is reserved. Brand and system names are protected and can’t be claimed." Taken → "{v}.privacyspace.com is already in use." Matches verified domain root (contains root, or root starts with it) → claimed instantly. Else → review queue (Admin) with message "…doesn’t match your verified domain ({vdom}), so a person checks it before it’s released. This usually takes one business day."
- Changing subdomain locked while live.
- Go live requires steps 1–3. Taking offline: form shows the privacy email instead; open cases unaffected.
- Rules: at least one request type and one law ("Select at least one request type and one law."). SLA = shortest of selected (GDPR/UK 30, CCPA 45). Changes apply to new requests only.
- Custom domain: must be a subdomain (`^[a-z0-9-]+(\.[a-z0-9-]+){2,}$`) → "Enter a subdomain such as privacy.{vdom}". Verified → SSL issued; subdomain redirects to custom domain.
- Mail: until verified, send from `no-reply@privacyspace.com` with reply-to the privacy email.

## Billing rules
Source of truth is **Stripe** (Stripe Billing). The app mirrors it via webhooks and never stores card data.
- **MRR** = sum of active and canceling subscriptions; annual = price / 12. Trials and past-due excluded. ARR = MRR × 12. "At risk" = price of past-due subscriptions.
- **Cash received** = succeeded payments minus refunds, grouped by payment date.
- **Overage**: DSARs received in the period above `included` × plan overage price; added to the next invoice (annual plans: billed monthly in arrears). **Intake is never blocked** by plan limits or unpaid invoices.
- **Failed payments**: provider retries on day 0, 4, 8 (prototype: 1, 5, 9 Oct). After the third failure the invoice is overdue and the subscription `past_due`. **Automatic suspension**: a daily job suspends the org `policy.dunning` days (default 3) after the final failed attempt, actor `System`, category Billing, reason "{invoice} unpaid {n} days after the final failed attempt on {date}." Warning emails to the owner at the final failure and 1 day before suspension. (Previously: manual, with reason). Suspension keeps portals live and deadlines running.
- **Retry payment** (admin/billing, reason): charges now; on success invoice → paid, subscription → active. If the org was suspended for non-payment it is **reactivated automatically** (System audit "Reactivated {org} automatically after payment"); toast "Payment received. {org} reactivated automatically." The same happens on `invoice.paid` from Stripe (customer pays via Customer Portal or Stripe's own retry). Manual (non-billing) suspensions are never lifted automatically. Track `suspensionKind: 'non_payment' | 'manual'`.
- **Extend trial**: +7 or +14 days, reason; owner emailed.
- **Apply credit**: €25 / €50 / €100, reason shown on the invoice; reduces next invoice.
- **Cancel at period end** (danger, reason) / **Resume**. After end: members lose access; open cases and evidence packs downloadable for 30 days.
- **Refund** (danger, reason shown to customer): full payment; creates a negative payment row; original shows "Refunded".
- **Void invoice** (danger, reason): no longer owed; if it was the past-due invoice, subscription returns to active.
- **Send reminder**: emails the org owner; logged.
- Customer side (Settings › Billing & usage, workspace Admin only): change plan (upgrade now, prorated; downgrade at renewal; can't downgrade below current workspace count), cancel (reason), update payment method (provider-hosted page), edit billing details. All logged in the workspace audit.
- Every staff billing action writes a `Billing` staff audit event.

## Requester portal rules
- Sign-in: email → always show "Check your email" (no enumeration). Link + 6-digit code, single use, 15-minute expiry; "Send a new code" invalidates older codes. Rate-limit 5 per email per hour, 20 per IP per hour.
- Session scoped to workspace + email; 30-minute idle timeout.
- Shows requests where `requester.email` matches (case-insensitive) in this workspace only.
- Status mapping and copy: docs/03 § H2. Never expose internal notes, system names, staff names, risk, audit.
- Info requested (from "Request more information"): show the matching ask; upload is stored as a case file `requester_upload`, logs "Requester uploaded {item}" (actor "{Name} (requester)"), notifies the case owner (new Handler notification "Requester replied"), and sets `infoRequested=false`. The SLA is unchanged.
- Messages: inbound message creates a Communication (Inbound, Portal) + Handler notification. Outbound comms appear here in requester-safe wording.
- Documents appear only after **Send response** on a Completed case; links are signed and expire 7 days after first open. Files are deleted with the raw-export purge (30 days after closure); the download note says so ("The files are deleted on {date}, 30 days after we closed your request. This record of your request stays here.").
- **After deletion the request stays visible** for the workspace retention period: status, timeline, request details and messages. The documents card becomes: "We deleted the files for this request on {date}, 30 days after we closed it, as our retention policy requires. The record of what you asked for, what we did and our messages stays here." When the case itself is deleted at retention end, it disappears from the portal.
- Rejected: show "Closed" with the documented reason sent to the requester and the right to complain.

## Admin rules
- Support can't change plan, MFA, suspension, reserved names, staff, policies (UI shows lock notes; enforce server-side).
- Suspend (manual by Platform admin, or automatic for non-payment — see Billing rules): members can’t sign in; **portals stay online and keep accepting requests; deadlines keep running**; owner emailed. Suspended orgs can't receive support-access requests.
- Support access: request → customer owner approves in their workspace (**NOT MOCKED** customer side) → active for ≤ policy max hours → auto-expire job → ended. Shown in the customer’s audit log. Removing a staff member ends their active grants.
- Approving a subdomain sets that workspace's portal to setup state; reject shows reason to the customer; reject-and-reserve adds to reserved list.
- Policies: "Customers can be stricter, never looser."
- Overview attention items: pending reviews (flagged = bad tone), non-ok domains, overdue invoices ("Payment failed · {org}"), orgs without MFA (not suspended).
- Billing role: may perform billing actions only; Support sees billing read-only.
